    Лабораторная работа 2: Параллельный парсинг веб-страниц

    Обзор задания

    Разработать три программы на Python для параллельного парсинга веб-страниц с сохранением данных в базу данных. Каждая программа использует различный подход к параллелизму:

    1. Threading - многопоточность
    2. Multiprocessing - многопроцессность
    3. Async/Await - асинхронное программирование

    Источник данных

    Сайт для парсинга: https://quotes.toscrape.com/

    Каждая страница содержит 10 цитат, взято 40 страниц

    Цель работы

    Изучить три подхода к параллельному программированию в Python

    Реализовать функцию parse_and_save(url) для каждого подхода

    Сохранить данные в БД из лабораторной работы 1

    Замерить и сравнить время выполнения каждого подхода

    Проанализировать эффективность каждого метода

    Технологический стек

    Реализованные подходы

    Threading подход (ex_threading.py)

    Принцип работы:

    • Создаётся поток для каждого URL
    • Все потоки работают в одном процессе
    • GIL (Global Interpreter Lock) может ограничивать производительность

    Реализация:

    def threading_parser(urls):
    threads = []
    for url in urls:
        thread = threading.Thread(target=parse_and_save, args=(url,))
        threads.append(thread)
        thread.start()

    for thread in threads:
        thread.join()  # Ждём завершения

    Особенности:

    • Простая реализация
    • Низкое потребление памяти
    • Хорошо для I/O операций
    • GIL ограничивает CPU-bound задачи
    • Может быть медленнее для чистого вычисления

    Когда использовать:

    • I/O bound операции (сетевые запросы, файлы)
    • Небольшое количество потоков (< 100)
    • Нужна максимальная простота

    Multiprocessing подход (ex_multiprocessing.py)

    Принцип работы:

    • Создаётся отдельный процесс для каждого URL
    • Каждый процесс имеет свой интерпретатор Python
    • Отсутствует GIL, но выше накладные расходы

    Реализация:

    def multiprocessing_parser(urls):
    processes = []
    for url in urls:
        process = multiprocessing.Process(target=parse_and_save, args=(url,))
        processes.append(process)
        process.start()

    for process in processes:
        process.join()  # Ждём завершения

    Особенности:

    • Без GIL, полный параллелизм
    • Хорошо для CPU-bound задач
    • Масштабируемо
    • Высокое потребление памяти
    • Накладные расходы на создание процессов
    • Сложнее с общей памятью

    Когда использовать:

    • CPU-bound операции (вычисления)
    • Независимые задачи
    • Нужен полный параллелизм

    Async подход (ex_async.py)

    Принцип работы:

    • Асинхронная обработка множества операций в одном потоке
    • Использует event loop для управления операциями
    • Очень эффективно для I/O операций

    Реализация:

    async def async_parser(urls):
    async with aiohttp.ClientSession() as session:
        tasks = [parse_and_save(session, url) for url in urls]
        await asyncio.gather(*tasks)

    Особенности:

    • Самая низкая заранее выделенная память
    • Максимальная скорость для I/O операций
    • Один поток = минимальные переключения контекста
    • Масштабируемо на 1000+ одновременных операций
    • Более сложный код
    • Нужны асинхронные библиотеки (aiohttp)

    Когда использовать:

    • I/O bound операции
    • Множество одновременных операций
    • Максимальная производительность важна

    Анализ результатов

    Threading

    • Время: 2-3 сек
    • Причина медленности: GIL ограничивает параллелизм, но для I/O операций эффект минимален
    • Преимущества: Простая реализация, низкая память
    • Недостатки: Может быть медленнее из-за переключения контекста

    Multiprocessing

    • Время: 3-4 сек
    • Причина медленности: Накладные расходы на создание процессов и Inter-Process Communication (IPC)
    • Преимущества: Без GIL, лучше для CPU-bound задач
    • Недостатки: Высокая память, медленнее для I/O операций

    Async

    • Время: 1-2 сек (САМЫЙ БЫСТРЫЙ)
    • Причина скорости:
    • Минимальные переключения контекста
    • Одна очередь событий вместо переключений между потоками/процессами
    • Оптимизирован для I/O операций
    • Преимущества: Максимальная скорость для I/O, минимальная память
    • Недостатки: Более сложный код

    Вывод по скорости

    Async > Threading > Multiprocessing (для I/O операций)

    Async быстрее в 2-3 раза из-за отсутствия накладных расходов на управление потоками и процессами.

    Выводы

    Полученные знания

    1. Threading: Подходит для I/O операций, но ограничен GIL. Легко реализовать, но может быть непредсказуем в производительности.

    2. Multiprocessing: Избегает GIL, но имеет значительные накладные расходы. Лучше для CPU-bound задач, но медленнее для I/O операций.

    3. Async: Самый быстрый для I/O операций благодаря минимальным накладным расходам. Требует асинхронных библиотек и более сложного кода.

    Сценарий Рекомендуемый подход

    Максимальная производительность Async
